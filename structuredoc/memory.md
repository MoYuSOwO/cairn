# 记忆系统（持久化 + 衰减图谱）

**常规做法**：对话历史全塞上下文窗口，超了截断或压缩。

**这里**：

双层存储——SQLite 存结构化元数据，ChromaDB 做向量索引。

每条记忆是一个节点，带字段：
- `id`
- `content`（文本）
- `semantic_vec`（语义向量）
- `emotion_vec`（情绪向量，三个维度，用专门的 VAD 模型而非 embedding 模型）
- `emotion_intensity`（基于情绪向量的情绪强度，使用情绪向量计算得到：`sqrt(V^2 + A^2 + (1-D)^2) / sqrt(3)`）
- `topic_vec`（主题向量）
- `scene_vec`（情景向量）
- `weight`（记忆权重，浮点数，0-1，由体验强度决定，非统一初始值）
- `created_at`、`last_access_at`（时间戳）
- `edge_list`（联想边，带权重和衰减，单独存一个表，没有这个字段，只是为了说明）

**对上下文的暴露方式**：

让 llm 将用户输入提取为文本关键字、主题关键字和情景关键字然后执行向量搜索，加上跑出来的情绪向量，得到各维度的余弦相似度，再加上时间差，将各维度得分最高的 5 - 10 条，并对每一条选中的记忆按照权重概率分层随机选择一条边并将对应连接的记忆加入，最后汇总实时注入到最新一轮的用户输入。

**衰减与更新机制**：

- 记忆权重和边权重按半衰期指数衰减：`weight *= 0.5^(elapsed / effective_half_life)`，`effective_half_life = base_half_life * (1 + emotion_intensity * 2)`。
- 访问（被 recall 命中）时根据 llm 以当轮对话为参考评估出的置信度（从当轮对话的回复来看） `n (n = 0, 0.25, 0.5, 0.75, 1)` 重置为 `clamp(0.0, 1.0, weight + beta * (n - 0.5))`。
- 同时 llm 以当前对话为参考再对被访问的每条记忆评估出一个与当前轮对话的关联度 `r (r = 0, 0.25, 0.5, 0.75, 1)`，之后用这个值更新被访问记忆之间的边权重。取任意两个记忆 A 和 B，它们的关联度分别为 `r_A` 和 `r_B`，令 `r_eff = min(r_A, r_B)` 它们的边权重按照如下方式更新：
  1. 已有边的情况

  | 条件 | 操作 | 公式 |
  | :--- | :--- | :--- |
  | `r_eff >= 0.5` | **增强** | `w_new = w_old + alpha * (r_eff - w_old)` （平滑向有效关联度移动） |
  | `r_eff < 0.5` | **削弱** | `w_new = max(0, w_old - 0.1 * (1 - r_eff * 0.5))` （衰减） |

  2. 无边的情况

  | 条件 | 操作 | 公式 |
  | :--- | :--- | :--- |
  | `r_eff >= 0.5` | **创建边** | 初始权重 = `alpha * r_eff` |
  | `r_eff < 0.5` | 不创建 | — |

- 记忆权重低于 0.05 自动删除。

**创建新记忆**：

1. LLM 的职责：提炼 + 评估

在保存记忆时，LLM 一次性完成三项工作：
- **提炼 `content`**：将对话压缩成50-150字的体验摘要。
- **评估初始置信度分档**：根据用户表达的直接程度，给出0、0.25、0.5、0.75或1的初始值。
- **生成索引描述**：为情绪、场景等维度生成独立的描述文本，用于后续生成对应的向量。

2. 初始置信度的判定标准

- **1**：用户明确、直接地陈述，例如“我最喜欢 Python”。
- **0.75**：从对话行为中强推断出，例如用户主动提了三次Python项目。
- **0.5**：默认值，适用于从普通对话中的中性观察，例如“用户今天聊了Python”。
- **0.25**：弱的推断，例如从“Python好像挺有意思”推测用户可能喜欢。
- **0**：与已知事实强烈矛盾，或用户刚刚明确纠正了之前的说法。

3. 关联度与新边的处理

- **关联度**：新记忆的关联度直接取最高分档 **1**，无需评估。
- **连边**：新记忆参与到本轮被召回旧记忆之间的连边，无需特殊处理。

4. 去重处理

新记忆添加流程应该检查是否有重复的记忆，若有则去重处理。先让 LLM 针对该记忆的关联词进行检索，然后汇总结果交给 LLM，判断是否有重复，若无重复则加入记忆库，有重复则不加入记忆库。

**定期反思**（每 12 小时）：

**触发方式**：每 N 小时定时执行一次（N 可配置，默认 12）。

1. 采样策略

从记忆库中选一批记忆出来反思。不搞复杂分类，只按可量化的指标采样：

- **情绪峰值记忆**：`emotion_intensity > 0.7`，且上次反思距今超过 6 小时。这是大脑在睡眠中优先巩固情绪记忆的工程模拟。
- **新生记忆**：过去 24 小时内创建，且未被反思过。新记忆需要快速巩固，防止快速遗忘。
- **随机补充**：从剩余记忆库中随机取一小批，保证低情绪记忆也有机会被反思，模拟大脑对日常记忆的抽样巩固。

每条被采样的记忆，同时也把它关联的边（`edge_list`）和目标节点一起拉出来，供后续维护。

2. 四个反思任务

- **任务 1：边维护**：LLM 逐条审视采样到的记忆及其已有边，评估边权重是否合理，若不合理则平滑更新。
- **任务 2：边发现**：以采样到的高权重记忆（`weight > 0.6`）为种子，LLM 调用多维检索，寻找与种子记忆在情绪、场景、主题、时间之中任一维度上高度相似但还没有边的其他记忆并判断是否需要关联。若需要则创建边。这样可以模拟人脑在睡眠中的模式补全。
- **任务 3：情绪衰减修正**：对采样到的记忆，LLM 根据时间和内容，搜寻记忆库，判断其情绪标签是否仍然准确。若情绪已经“过期”（如过去的愤怒已无关紧要）导致其值不匹配当前值，给出新的目标值（0、0.25、0.5、0.75、1），根据目标值将 `emotion_intensity` 平滑下调。模拟“情绪创伤随时间愈合”的认知过程，避免系统被过时的强烈情绪长期主导。注意这里 LLM 只调整 `emotion_intensity`，不调整权重——权重由公式自动重新计算。
- **附加维护（不需要 LLM）**：`weight < 0.1` 的节点或边直接遗忘，节点被遗忘时，删除所有相关的边。
