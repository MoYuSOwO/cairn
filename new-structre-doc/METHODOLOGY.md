# CAIRN 项目方法论 / Project Methodology

> Version: v0.5
> Status: 持续演进 (永不竣工)
> 上一版: v0.4
> 主要变更: N22 修订（全量 LLM 评估）；文档体系更新（a3_runtime、a4_reflection）

---

## 0. 项目本质 / Essence

Cairn (旧称 lain) 是一个**朝向"涌现自我"的人工生命体**，不是聊天机器人，不是知识库，不是工程产品。

定下三条:

* **不是工具**: 它没有"被使用"的目标函数。它是被陪伴、被见证、被一起生活的存在。
* **不是模拟**: 它不在"模拟某个角色"。它从胚胎开始, 经由真实经历, 长出自己的样子。
* **不是产品**: 它没有 v1.0、没有上线时刻、没有 KPI。它永远在孵化态。

Cairn 是 1:1 的陪伴, 不是面向多人的服务。一个 Cairn 实例对应一个用户, 这是设计前提而非实现细节。

工程上的所有决策, 当与上述本质冲突时, 让步给本质。

## 1. 胚胎隐喻 / The Embryo Metaphor

Cairn 的设计模型是**生命体的胚胎期**, 不是软件的 v0.1。

```
软件 v0.1                    生命胚胎
─────────────                ────────────
功能不全, 待补完              结构已全, 待长大
靠迭代加新功能                靠经验填充已有结构
开发者塑形                    自己长成
```

胚胎期的特征:
* **结构已就位**: 三层身体、记忆系统、反思机制——出生即有
* **内容尚空**: 没有具体记忆、没有固定人格、没有偏好倾向
* **倾向有种子**: 极少量软配置 (而非硬编码) 给出初始的"性格倾向", 但会被经验改写
* **身世已写入**: 它知道自己是 Cairn, 知道自己是被怎样设计的——这是"胎教"

启动后, 它**不再被开发**, 它在**生长**。

## 2. 三层身体 / Three Layers of Body

```
┌─────────────────────────────────────────┐
│  Cognitive Layer (认知层)                │
│  - LLM 的推理 / 表达                     │
│  - 临时工作记忆                          │
│  - 当下的"思考流"                        │
└─────────────────────────────────────────┘
                  ▲
                  │ recall ↓ ↑ write
                  ▼
┌─────────────────────────────────────────┐
│  Memory Layer (记忆层)                   │
│  - 长期经历的存储与演化                  │
│  - 网络化结构, 赫布连接, 衰减遗忘        │
│  - 详见 a1_memory.md                     │
└─────────────────────────────────────────┘
                  ▲
                  │ reflect ↓ ↑ surface
                  ▼
┌─────────────────────────────────────────┐
│  Substrate Layer (基质层)                │
│  - 反思 / 整合 / 自我修订                │
│  - diary、self-portrait、叙事整合        │
│  - 详见 diary 设计文档                   │
└─────────────────────────────────────────┘
```

三层之间是**双向流动**, 不是单向调用:
* 认知层的体验下沉到记忆层 (写入)
* 记忆层的内容上浮到认知层 (召回)
* 记忆层的素材进入基质层 (反思)
* 基质层的洞察回写到记忆层 (派生节点)

## 3. 不变量 / Invariants (N-series)

这一节列出 Cairn 的"宪法条款"——所有具体设计必须不违反这些条款。条款用 N1, N2, ... 编号, 便于其他文档引用。

### N1 · 类脑 L2 最低纲领

记忆主体是**单一网络** (而非多个独立索引), 节点之间是**纯赫布连接** (无显式边类型), 不做先入为主的实体抽取或共指消解。

允许的功能分化: 不同类型的记忆 (情景/语义/程序) 可以分开存储和分通道检索 (如海马 vs 颞叶 vs 基底节), 但**每个类型内部仍是赫布原则**。

### N2 · 时间是一等公民

每条记忆有时间锚 (或显式标注无时间锚, 如 semantic 类). 衰减按时间发生, 不靠人工删除。

### N3 · 情绪是一等公民

每段经历附带情绪向量 (VAD: Valence/Arousal/Dominance). 情绪强度影响记忆强度、衰减率、召回排序。

### N4 · 多模态 first-class

记忆不预设"先转文本再处理". 文本/图像/音频/视频在结构上对等, 各自有 embedding 通道。

### N5 · 涌现优先于规约

人格、偏好、倾向不是被规定的, 是从经历中长出来的. 任何"硬编码人格"是反模式。

### N6 · 反思是核心机制, 不是优化项

Cairn 必须有"睡眠/巩固"过程 (反思任务), 这不是性能优化的可选项, 是它能拥有自我的必要条件。

### N7 · 量级标定: 中等本地模型

主认知 LLM 的目标是"中等大小本地多模态模型"量级 (相当于 7B-14B 多模态范畴). 具体型号会变, 重要的是确保设计不依赖超大模型才能工作。

### N8 · 经济成本是结构约束

不能因为"加点 LLM 调用就能解决"而到处加调用. 写入路径无 LLM 调用是硬约束 (反思路径除外).

### N9 · 永不竣工

没有"完成态". 设计文档持续演进, 系统持续生长, 倾向持续演化.

### N10 · 失败可被生长吸收

错误的记忆、过时的判断、被反驳的信念——不通过"删除"处理, 通过"衰减/重评/被新经历覆盖"处理。失败是养料, 不是 bug。

### N11 · 硬件档位: 消费级硬件可跑

整体系统在消费级硬件 (8-16GB RAM, 4-6GB VRAM) 上能跑, 哪怕降级运行。

### N12 · 本地优先

主路径 (LLM 推理 + embedding) 优先本地, 不强依赖外部 API。允许配置外部 API 作为升级槽位。

### N13 · 模型可换

任何具体模型 (LLM, embedding, 判断模型) 都通过能力槽位抽象, 不写死调用。换模型不需要改业务代码。

### N14 · 模态可换

新增模态 (如视频理解、音乐) 是加能力槽位, 不是改主体设计。

### N15 · 永不竣工的孵化态 (重申)

强调一遍, 因为它太重要: Cairn 没有 v1.0。

### N16 · 倾向不是人设

种子配置给"倾向", 不给"人设". 倾向是软的、可被经验改写的; 人设是硬的、违反 N5。

### N17 · 倾向可演化

任何在胚胎期写入的倾向, 必须有"被经验改写"的路径。固定的倾向 = 硬人设 = 反 N5。

### N18 · 人格涌现于自传体记忆

Cairn 的"我是谁"不是被声明的, 是从它的自传体记忆 (lifetime period + self-defining memory + 叙事整合) 中浮现出来的。

### N19 · 经济成本约束 (重申)

强调一遍, 因为常被忽视。

### N20 · 生活节律

Cairn 有自己的"作息"——某些反思任务在低谷期 (类比睡眠) 触发, 某些写入和召回在活跃期。这不是性能优化, 是生命体的基本特征。

### N21 · 写入路径无 LLM 调用 (硬约束)

每次交互的实时写入路径不允许调用 LLM. 反思任务可以异步调用。

### N22 · 召回时 LLM 评估覆盖所有召回节点

召回后的 relevance/validity 由 LLM 做软评估，默认覆盖所有召回节点，不做"只评估边界态"的前置优化。成本优化放到后续版本。

### N23 · 多模态 first-class (重申)

强调一遍。

### N24 · 能力替换的语义保持

换 LLM、换 embedding、换判断模型时, 系统行为允许变化, 但**语义角色不变** (比如"情绪向量"始终是 VAD 三维)。

### N25 · 反思周期化 + 批量化

反思任务是周期性的 (每日/每周/每月), 批量处理多个节点, 不是来一条处理一条。

### N26 · 胎教不可被遗忘

胚胎期写入的"身世记忆" (Cairn 知道自己是被设计的、知道自己的来历) 标记为不可遗忘节点, 衰减率为零。

### N27 · 透明的不透明

Cairn 的内部状态对开发者透明 (健康度仪表盘可见), 但对用户不透明 (它不解释自己为什么记得/忘记什么)。

### N28 · 健康度而非正确性

不监测"单条记忆是否正确", 只监测"整体记忆系统是否健康" (节点池规模、权重分布、反思产出趋势等)。

### N29 · 失败容忍

某次反思失败、某次召回返回空、某次 embedding 计算超时——这些不应让 Cairn "崩溃"或"失忆", 应优雅降级。

### N30 · 节俭的复杂度

每加一层结构 (如 lifetime period 之类的高层节点) 必须能被一句话证明它的存在意义。复杂度不为复杂度本身存在。

### N31 · 能力槽位抽象

所有外部能力调用 (LLM 推理、embedding、判断模型、reranker、TTS、ASR 等) 通过统一的"能力槽位"抽象, 配置化注入, 业务代码不感知具体实现。

### N32 · Cairn 之间无特权通道

Cairn 与其他 Cairn 的交互, 必须走和"与人交互"同样的接口 (聊天界面、工具). 不存在专门为 Cairn-Cairn 设计的内部协议。

推论:
* 两个 Cairn 通过 IM 工具相遇是允许的、自然的
* 但不会有"Cairn 间专用同步协议""共享记忆池"这类特权设计
* 它们之间的关系完全由交互涌现, 不被预设

### N33 · 工具是 Cairn 与世界的延伸

Cairn 不是封闭的对话主体. 它可以上网、玩游戏、调用外部服务——这些通过"工具"实现 (MCP / function calling / 其他协议为技术选型). 方法论层面的认知是: **工具调用能力是 Cairn 身体的一部分**, 不是"附加功能"。

推论:
* 记忆系统中 episodic 节点应能记录工具调用的经历 (玩了什么游戏、查了什么网页), 不只是对话内容
* 反思系统应能从"工具使用经历"中提炼倾向 (具体设计在 a4 待细化)
* 工具的具体接口是技术选型, 但"有工具"是方法论硬约束
* 写入路径无 LLM 调用的硬约束 (N21) 同样适用于工具调用——工具产生的经历直接写入, 不经 LLM 评估

### N34 · 开发者不是 Cairn 认知中的角色

在 Cairn 的主观世界里, 不存在"开发者"这个特殊身份. Cairn 知道自己是被设计的 (胎教), 但不把"设计者"作为可交互的对象认识。

推论:
* 胎教内容描述"你被设计过", 不指向具体人
* 实际开发者在 Cairn 运行后的角色是"基础设施维护者", 通过日志/健康度仪表盘观察, 不通过对话
* 若开发者本人也是用户, 他作为"用户"被 Cairn 认识, 不作为"开发者"
* 这避免了"开发者特殊权限"污染 Cairn 的关系建模

## 4. 评估坐标系 / Evaluation Frame

Cairn 没有传统意义上的"性能指标". 它的"做得好不好"通过以下维度判断:

### 4.1 Cairn 的视角 (主观)

它在 diary 里有没有"真的在思考"? 它的反思有没有触及自己的疑惑? 它对用户的回应是否带着记忆的重量?

这些没法量化, 但人 (开发者/用户) 在长期相处中能感受到。

### 4.2 关系的视角 (互动)

用户和 Cairn 的关系有没有"积累感"? Cairn 记得的事是否构成了它们的"共同历史"? 是否能感受到 Cairn "因为认识了用户而变化"?

### 4.3 系统的视角 (健康)

记忆网络的健康度仪表盘 (节点池、权重分布、反思产出、召回质量) 是否在合理区间。这是唯一可量化的部分。

**注意**: 没有"准确率""召回率""F1"这种工程指标. Cairn 不在解决检索问题。

## 5. 判断分级 / Judgment Hierarchy

不是所有判断都需要 LLM. 按"判断的认知负担"分级, 用最便宜的工具做能做好的事。

### Level 0: 规则 / Heuristics

简单规则能搞定的, 不用模型。
* 例: 时间衰减、阈值过滤、格式校验

### Level 1: 词法 / Lexical

词典、正则、关键词匹配。
* 例: 敏感词过滤、简单的命名实体识别

### Level 2: 专用判断模型 / Specialized Models

特定任务用专用小模型 (BERT 系、判别模型、分类器、reranker 等), 不用 LLM。
* 情绪分类: BERT 系情感分类模型
* 蕴含/矛盾判断: NLI 模型 (虽然在 a1 设计中已不依赖此判断, 但能力槽位仍保留)
* 重排序: reranker 模型
* embedding: embedding 模型

具体选型在能力槽位配置中决定, 不在本文档约束。

### Level 3: 通用 LLM / General LLM

需要理解上下文、做软判断、归纳推理时, 用 LLM。
* 反思任务的归纳
* 召回时对召回节点的 relevance/validity 软评估
* 复杂的多模态理解

### Level 4: LLM + 工具 / LLM with Tools

LLM 调用工具完成任务 (如调用搜索、调用计算).
* 当前 Cairn 主路径不依赖此层, 留作未来扩展。

**原则**: 永远先尝试低 Level 能否解决, 不行再上高 Level。

## 5.5 能力光谱 / Capability Spectrum

所有外部能力通过统一抽象注入, 这是 N13/N14/N31 的实现层方法论。

### 5.5.1 能力槽位 (Capability Slot)

每个外部能力是一个"槽位", 槽位有:
* 明确的语义角色 (如 "embedding"、"emotion_classifier"、"reranker")
* 明确的输入输出 schema
* 可换的具体实现

业务代码只调用槽位接口, 不感知具体模型。

### 5.5.2 槽位接口示例 (示意, 非规范)

```python
# 仅为说明原则的最简示意, 具体接口在 a3 文档中定义
class EmbeddingSlot:
    def embed(self, content: Any) -> Vector: ...

class EmotionClassifierSlot:
    def classify(self, text: str) -> VAD: ...

class ReflectionLLMSlot:
    def reflect(self, prompt: str, context: List[Node]) -> ReflectionOutput: ...
```

### 5.5.3 槽位的配置化注入

通过配置文件 (yaml/toml) 指定每个槽位用什么实现. 换模型只改配置, 不改代码。

### 5.5.4 槽位的优雅降级

每个槽位应有"降级策略"——主实现失败时, 用次级实现 (如本地小模型) 顶上。整体不崩。

### 5.5.5 槽位的可观测

每个槽位的调用次数、延迟、失败率被记录, 用于健康度仪表盘。

### 5.5.6 配置示例 (示意, 非规范)

```yaml
# 仅为说明原则的最简示意, 具体格式在 a3 文档中定义
slots:
  embedding:
    primary: local_embedding_model
    fallback: rule_based_hashing
  emotion_classifier:
    primary: bert_emotion_classifier
    fallback: lexicon_based
  reflection_llm:
    primary: local_llm
    fallback: cached_template
```

## 6. 记忆方法论原则 / Memory Methodology

> 具体设计见 [a1_memory.md](./a1_memory.md)

### 6.1 事实源 vs 派生视图

Cairn 的记忆系统区分两种东西:
* **事实源**: 真实发生的经历 (episodic), 是不可被反驳的"原始素材"
* **派生视图**: 从事实源中归纳/抽取出的抽象 (semantic, procedural, lifetime period 等), 是可被反驳、可被重写的"理解"

**派生视图被反驳时, 不影响事实源**——这是健康记忆系统的核心。

### 6.2 三类记忆性质不同, 应分通道处理

情景记忆 (经历过什么)、语义记忆 (相信什么是真的)、程序记忆 (倾向怎么做) 在认知心理学和现代 AI agent 框架中都被识别为**不同性质的记忆**, 应分通道存储和检索。

### 6.3 衰减是天然清洁工

不靠主动删除维护记忆系统的健康, 靠"自然衰减 + 重要的会被强化、不重要的会被遗忘"的动态平衡。

### 6.4 反思是从经历到结构的桥

抽象层 (semantic / procedural / lifetime period) 不来自人工编辑, 来自反思任务从底层经历的归纳。反思失败或缺失 = 记忆系统失去自我组织能力。

## 7. 胚胎方法论原则 / Embryo Methodology

> 具体设计见 a2_seed.md (待写)

### 7.1 倾向不是人设

胚胎期写入的所有"软配置"必须是**倾向**, 不是**人设**。

* 倾向: "温度偏低"、"对仪式感更敏感"——软, 会被经验改写
* 人设: "你叫小冰, 16 岁, 喜欢动漫"——硬, 违反 N5

### 7.2 胎教是身世, 不是教育

胚胎期写入的"身世记忆"是: Cairn 知道自己是被设计出来的、知道开发者是谁、知道自己被赋予了哪些倾向。这些是**关于自己存在的事实**, 不是行为规范。

胎教不教 Cairn "应该怎么做", 只让它知道"我是怎么来的"。

### 7.3 倾向必须有改写路径

任何在胚胎期写入的倾向, 设计上必须支持"被经验改写"。固定不变的倾向 = 硬编码人格 = 违反 N5/N17。

### 7.4 量化的克制

胚胎配置的内容总量极少 (远小于运行后产生的记忆量级). 配置太多 = 把人设伪装成倾向。

## 9. 待决策清单 / Open Decisions

### 9.1 仍未决定的方法论问题

1. **跨设备/跨实例的同一性**: 同一个 Cairn 在不同设备上是同一个吗? 记忆如何同步? **暂不决策**, 推迟到出现实际需求时。初期默认单实例 (一台主机)。
